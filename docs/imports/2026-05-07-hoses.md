## How to re-run

```sh
# Preview only (no DB changes):
pnpm --filter @indus/db db:import src/imports/2026-05-07-hoses.ts --dry-run

# Live (idempotent — safe to re-run; specs/FAQs are NOT clobbered by default):
pnpm --filter @indus/db db:import src/imports/2026-05-07-hoses.ts

# To replace specs/FAQs with the data-file values (CLOBBERS admin manual edits):
pnpm --filter @indus/db db:import src/imports/2026-05-07-hoses.ts --mode=overwrite-edits

# To update only the Product row fields (price, status, descriptions) without
# touching specs/FAQs (useful for pricing-only re-runs):
pnpm --filter @indus/db db:import src/imports/2026-05-07-hoses.ts --mode=update-only
```

## Editing brand & category metadata after import

Important: the dedicated `/admin/brands/[id]/edit` and
`/admin/categories/[id]/edit` pages are **SEO-only stubs** — they do NOT
expose the core fields (`isAuthorizedDistributor`, `country`, `parentId`,
`defaultSpecTemplateId`, `position`, `isPublished`).

Edit core fields via the **inline modals on the list pages**:

- `/admin/brands` — click a row to open the modal (country, authorised
  distributor toggle, published flag).
- `/admin/categories` — click a row to open the modal (parent, position,
  default spec template, published flag).

This asymmetry will be resolved when the brand/category core editor is built
(captured as a follow-up — out of scope for this PR).

## Cache invalidation

The CLI runs in a Node-only context, so it cannot call `revalidatePath` / `updateTag`
directly (those require the Next.js runtime). After running this import:

- **Storefront pages** rebuild on next request via Next.js's default revalidation.
- **Megamenu** picks up changes on next request — no manual bust needed because
  the storefront's `getNavMenu` reads from the DB on every request.

If you see stale pages on the production site, trigger a redeploy or clear the
ISR cache from the Vercel dashboard. (A dedicated `/admin/api/import/revalidate`
route handler is captured as a follow-up.)
